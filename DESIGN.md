# RelayOS design identity

RelayOS is an operations workstation for delivery teams, not a marketing dashboard. It should make owners, status, exceptions and evidence easy to inspect during sustained work. Existing green-and-white screens are a transitional implementation, not the final approved direction.

## Visual language

Use a calm graphite and neutral foundation, warm orange as a restrained focus/attention accent, and semantic status colors with labels rather than color alone. Support a considered light theme, not an inverted dark theme. Base all tones on contrast-tested tokens. Use consistent readable sans-serif text, tabular numbers, and monospace only for identifiers or technical values; provide local fallbacks. Avoid tiny labels.

Favor a clear page title, contextual navigation, meaningful tables and split panes over repeated decorative cards. Dense views should remain legible and support resizing, scrolling and responsive reflow. Use consistent spacing, subtle borders, little elevation, stable column alignment and purposeful whitespace. Icons supplement labelled actions; do not rely on icons alone. Motion should clarify state or context, never delay content; respect reduced-motion preferences. Initial design dials: ENERGY 2 / RHYTHM 2 / MOTION 1, subject to Design Read.

Use real records, explicit empty/loading/error states, visible focus and keyboard alternatives for drag actions. Give risky or consequential actions explicit confirmation. On narrow screens, preserve primary actions and readable content rather than shrinking desktop layouts. Avoid generic KPI placeholders, fabricated metrics, decorative animation, unlabeled statuses, and repeated charts without operational value.

The current UI requires a full Design Read, contrast review, keyboard audit, dark theme and upstream gate execution before it can be treated as finished. This document sets direction; it is not evidence that these checks passed.
